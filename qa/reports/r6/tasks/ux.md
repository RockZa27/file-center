Build first (`bun --bun run build`), your own PORT/STORAGE_DIR/DATA_DIR, start with `bun src/launcher.ts` (supervised, needed for updates). Browser context locale = the OTHER language from the page. Make sample files with a script: docx (Thai heading, table, image, header/footer), xlsx (2 sheets, dates, Thai, 1,500+ rows on one), ods, an old .xls if you can produce one, pptx (3 slides with Thai text and a picture), md (heading, list, table, a `<script>` and an `<img onerror>`), csv (Thai, commas inside quotes), a .ts file.
1. office-preview: open each file in the preview at 1200 and 375 px: content readable and correct (Thai renders, table cells line up, sheet tabs switch, dates show as dates, slides advance), the long sheet shows a "first rows only" note, the md script/onerror do nothing (no alert, no console error from them).
2. editors: edit and save md (live preview updates), csv as a table (add a row and a column, edit a cell with a comma, save, reopen: same data and quoting), .ts (highlighting, line numbers, Ctrl/Cmd+S saves).
3. edit-conflict: open the same .md in two tabs, save in tab A, then save in tab B: tab B is told the file changed; "load their version" shows A's text; repeat and choose "overwrite": B's text is saved.
4. office-button: without OFFICE_* env the "edit in Office" button is absent; restart with OFFICE_URL pointing at a tiny local stub server that serves `/web-apps/apps/api/documents/api.js` defining `window.DocsAPI = { DocEditor: function (id, cfg) { window.__cfg = cfg } }`, OFFICE_INTERNAL_URL=http://127.0.0.1:<port>, OFFICE_JWT_SECRET (32+ chars): the button appears for docx/xlsx/pptx, opening it requests /api/office/config and the stub receives a config with a token, document.url and (edit only) callbackUrl; a read-only user gets view mode (no callbackUrl).
5. one-step-update: local source (tiny HTTP server with latest.json + a package built with `bun scripts/package.ts --version <newer> --out <dir>`, app with UPDATE_SOURCE=http://127.0.0.1:<port>): dashboard shows the new-version warning with an Update button → update page opens the dialog → wrong password stays in the dialog → right password: steps, restart, page comes back on the new version. Then a source with a wrong sha256: the dialog says the download step failed, nothing installed.
6. alerts: ALERT_WEBHOOK_URL=http://127.0.0.1:<port>/hook (a local server that records requests), ALERT_WEBHOOK_KIND=discord: settings card shows on + host only; "send a test" arrives at the hook; fail logins until locked: an alert arrives once (not again for the next lockout within the hour) and contains no password.
7. language-and-mobile: switch to English: preview labels, editor buttons, update dialog, alerts card in English; at 375 x 812 nothing scrolls sideways in the preview, editors, update dialog and settings.
