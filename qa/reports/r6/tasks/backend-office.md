Office documents: edit docx/xlsx/pptx through ONLYOFFICE Docs (Community), and safer text saving. Another backend-dev changes src/routes/update.ts, src/update-source.ts, src/updater.ts and adds src/alerts.ts at the same time: stay out of those.

1. ONLYOFFICE integration (new `src/office.ts`, routes under `/api/office`), off unless configured:
   - env: `OFFICE_URL` (the document server as the browser reaches it, https or http://localhost…), `OFFICE_INTERNAL_URL` (how the document server reaches File Center, e.g. http://file-center:3000), `OFFICE_JWT_SECRET` (required; refuse to enable without one, at least 32 chars), optional `OFFICE_SERVER_INTERNAL_URL` (how File Center reaches the document server for downloading saved files, default OFFICE_URL).
   - `POST /api/office/config` `{ space, path, mode: 'edit'|'view' }` (signed in, CSRF; `read`+`download` for view, `write` for edit; only .docx .xlsx .pptx .odt .ods .odp .doc .xls .ppt .csv .txt within size limit `OFFICE_MAX_SIZE` default 100 MB): answers `{ apiUrl: <OFFICE_URL>/web-apps/apps/api/documents/api.js, config }` where config is the ONLYOFFICE editor config (document.fileType/key/title/url, documentType, editorConfig.callbackUrl/user/lang/mode, permissions.edit) plus `config.token` = JWT HS256 of the config with OFFICE_JWT_SECRET (implement HS256 with node:crypto, no new dependency). `document.key` = hash of space+path+mtime+size (changes when the file changes). `document.url` and `callbackUrl` use OFFICE_INTERNAL_URL and carry a token signed by File Center (HMAC, own key in DATA_DIR) binding space, path, user, mode and an expiry (24 h) — not the session cookie.
   - `GET /api/office/file/:token`: serves exactly the file the token names (re-check the user still has read/download and the file still exists), also verifies the document server's JWT in the `Authorization: Bearer` header when present (ONLYOFFICE sends it with JWT enabled; require it).
   - `POST /api/office/callback/:token`: verify the JWT (body.token or Authorization header) with OFFICE_JWT_SECRET; for status 2 and 6 download `url` — only from the document server's origin (OFFICE_SERVER_INTERNAL_URL/OFFICE_URL), size-limited, timeout — re-check the token's user still has `write` on that path, put the current file in the trash first (`moveToTrash` in src/trash.ts, so the old version can be restored), write the new content atomically, audit `office-save`; answer `{ "error": 0 }` (or `{ "error": 1 }` and log on failure). Other statuses: `{ "error": 0 }`. Only mode=edit tokens can save.
   - CSP: when OFFICE_URL is set, the web page CSP (WEB_HEADERS in src/index.ts) also allows that origin in script-src and frame-src (and connect-src if needed) — nothing else changes.
   - `GET /api/session` config tells signed-in users `office: { enabled, edit: [extensions], view: [extensions] }` so the page knows when to show the button.
   - docker-compose.yml: a `onlyoffice` service under profile `office` (pinned image tag of onlyoffice/documentserver, JWT_ENABLED=true, JWT_SECRET from OFFICE_JWT_SECRET, ports 127.0.0.1:${OFFICE_PORT:-8080}:80, restart unless-stopped, logging like the others); `.env.example` lines; README section: enabling (`COMPOSE_PROFILES=office`), RAM needs (~2–4 GB), Cloudflare Tunnel needs a second hostname for OFFICE_URL, the 20-connection limit of the free edition.
2. Safer text saving (`PUT /api/content` in src/routes/files.ts): accept optional `expectedMtime`; when given and the file's mtime differs, answer 409 `files.changed-elsewhere` without writing. `GET /api/content` already returns mtime; the answer of PUT returns the new mtime.
