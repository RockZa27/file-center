Build first if needed (`bun --bun run build`), your own PORT/STORAGE_DIR/DATA_DIR, start with `bun src/launcher.ts`. Browser context locale = the OTHER language from the page. This round changed security and speed, so the flows check that people still get through and get clear messages.
1. page-loads-fast: open the app cold: the main JS/CSS come back compressed (check the response header content-encoding br or gzip in Playwright), a reload gets 304 for unchanged assets (or is served from cache), no console errors; the file list of a folder with 2,000 files opens in under 1 s and is sorted like before (Thai and English names).
2. signed-updates: on the update page: it says signatures are required (built-in key); upload an UNSIGNED package (`bun scripts/package.ts --skip-web --version 99.0.0 --out <dir>`): refused with a clear message saying what to do; then restart the app with UPDATE_PUBLIC_KEY set to a throw-away key you make (`bun scripts/package.ts --gen-key <dir>`), build a package signed with it (`--sign <key>`), install it: works, page comes back on 99.0.0. Then restart with UPDATE_ALLOW_UNSIGNED=true: the dashboard and the update page show the warning.
3. login-limits: wrong passwords for one account from the page until the per-address or per-account lock: the page shows the wait time clearly (both languages); the right password during the wait is still refused with the wait message; the activity log shows login-failed entries with counts, not one line per attempt. (Set LOGIN_WIDE_WINDOW_MINUTES small or LOGIN_ACCOUNT_MAX_ATTEMPTS low via env to keep the flow short.)
4. password-change-lock: in the profile, change password with a wrong current password repeatedly: after the limit the page shows the lock message with a wait, not a generic error.
5. big-selection: select many files (e.g. 2,001 via the API or the page's select-all in a big folder) and download as zip / delete: the page shows the server's "too many items" message clearly instead of hanging; with 2,000 or fewer it works.
6. request-link-limits: create a request link without limits as admin: the public page shows the default limits (or that there are limits); uploading works; a file over the per-file default is refused with a clear message (set UPLOAD_REQUEST_MAX_FILE small via env for the test).
7. language-and-mobile: English and 375 x 812 for the update page, the login lock message, the request-link page: nothing scrolls sideways, all labels translated.
