1. Versions (new `src/versions.ts`, pattern of src/trash.ts):
   - Store: `DATA_DIR/versions/<sha1 of the storage path>/<id>/{item, meta.json}`, meta `{ id, storagePath, size, mtime (of the replaced content), savedAt, savedBy, reason: 'edit'|'office'|'restore' }`; ids validated like trash ids. Add the path to `paths`; skip `versions` in src/backup.ts (like trash).
   - Kept before content is replaced: `PUT /api/content` (src/routes/files.ts) and the ONLYOFFICE save (src/office.ts `saveVersion`: replace the `moveToTrash` of the old version by keeping a version). Limits `VERSIONS_KEEP` (default 10 per file, 0 = off) and `VERSIONS_DAYS` (default 30) in src/config.ts + .env.example; expired ones purged in `housekeeping()` (src/index.ts).
   - Quota: versions of a file in a user's home count against that user (src/quota.ts counting + reservations). When keeping a version would pass the quota, drop that file's oldest versions first; if still over, the save is refused with `quota.exceeded` (never silently lose the current content).
   - Routes (signed in or visitor with the same space permissions as today): `GET /api/versions?space&path` (`read`), `GET /api/versions/:id/download?space&path` (`download`), `POST /api/versions/:id/restore { space, path, expectedMtime? }` (`write`; the current content becomes a version first; 409 `files.changed-elsewhere` on a stale mtime), `DELETE /api/versions/:id?space&path` (`write`). Every route checks that the id belongs to that exact file (its meta storagePath equals the resolved path) — an id alone opens nothing. Audit `version-restore`, `version-delete`.
   - Rename/move of a file moves its versions with it; deleting a file (to trash) moves its versions into that trash entry so a restore from trash brings them back; purge removes them.

Favorites and recent (new `src/favorites.ts`): JsonStore `DATA_DIR/user-state.json` `{ [username]: { favorites: [{space, path}], recent: [{space, path, at}] } }` (max 200 favorites, 50 recent, newest first, no duplicates). Recent is recorded on download, preview/content read and save. Routes: `GET /api/me/favorites`, `POST /api/me/favorites { space, path }`, `DELETE /api/me/favorites { space, path }`, `GET /api/me/recent`. Reading drops entries that no longer exist or that the user can no longer `read` (permissions re-checked each time). Rename/move updates paths; deleting a user drops their state. Visitors (not signed in) have none (401).
3. Copy/move between spaces: `POST /api/copy` and `/api/move` take optional `destSpace` (default: the same space). Needs `read` (+`download` for copy) on the source space and `write` + `upload` on the destination space; the destination quota counts (copy and cross-space move); a cross-space move is copy then delete of the source, and leaves the source untouched if the copy fails. Never into the system folders (`guardSystemFolder`).
