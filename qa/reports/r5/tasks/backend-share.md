Share links: a signed-in user sends a link so someone without an account can download one file or one folder. Another backend-dev edits src/fsx.ts (moveSync) and src/routes/update.ts at the same time: keep your changes out of those, put your code in new files where you can (`src/shares.ts`, `src/routes/shares.ts`).

- Permission: new perm `share` in `PERMISSIONS` (`src/settings.ts`). Admins can always share; other users need `share` AND `download` on the space the item is in (`accessFor`/`need` in `src/auth.ts`/`src/context.ts`). Existing user records are not migrated (an admin grants `share` on the users page). Visitors (guest) can never create links, whatever guestPermissions says.
- Create `POST /api/shares` `{ space, path, days, password?, maxDownloads? }`: `days` one of 1, 7, 30 and at most `SHARE_MAX_DAYS` (env, default 30). Token: 32 random bytes, base64url; store only its SHA-256 (a stolen shares.json must not give working links); answer the token once at creation. Optional password hashed like user passwords (`hashPassword`/verify in `src/auth.ts`), min 6 chars. Store in a `JsonStore` (`src/store.ts`): id, tokenHash, owner, space, path (space-relative), type file/dir, createdAt, expiresAt, maxDownloads, downloads, passwordHash?, revokedAt?.
- Mine: `GET /api/shares` (owner's links, never the hash), `DELETE /api/shares/:id` (owner or admin). Admin: `GET /api/admin/shares` (all).
- Public (no session needed, CSRF exempt only for these GETs and the password POST): `GET /api/s/:token` → `{ name, type, size, expiresAt, needsPassword, entries? }`, entries for a folder share listed by `?path=` inside it (never outside: `resolveIn` on the shared folder as root, links skipped); `POST /api/s/:token/unlock` `{ password }` → sets a short-lived cookie scoped to that link; `GET /api/s/:token/download?path=` streams a file (same headers/sandbox CSP as `/api/download`), a folder share's subfolder or whole folder as zip (reuse the existing zip code). Each completed download counts once toward maxDownloads.
- A link stops working (same 404 "link not found or expired" for every case, so a guesser learns nothing) when: expired, revoked, maxDownloads reached, the item was deleted or moved (path no longer exists or type changed), the owner was deleted or lost `share`/`download` on that space. Password guesses: lock after 5 wrong tries per link+IP for 15 minutes (reuse the login lockout helper if it fits).
- Failed public download navigations get the HTML error page from r4 (`errorPage` in `src/context.ts` covers download routes: add the share download route to its list).
- Audit (`audit()`): share-create, share-download, share-revoke with the path, never the token. Logs: make sure `/api/s/<token>` URLs are scrubbed in system/access logs (`scrub`/`safePath` in `src/logger.ts`).
- Expired links are cleaned up from the store at start and once a day.
