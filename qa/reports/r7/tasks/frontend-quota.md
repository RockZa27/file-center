Web pages for "request files" links and quota feedback (the server side is already on the base: read src/routes/shares.ts, src/shares.ts, src/quota.ts, src/uploads.ts and tests/upload-links.test.ts, tests/quota.test.ts for the exact shapes and error codes). The account/2FA pages were done just before you: do not change them.

1. Share dialog (web/src/components/ShareModal.vue): for a folder, a choice "Let people download" / "Ask people to send files" (`kind: 'upload'`, only offered when the user has `upload` in that space — see the spaces in the store). Upload kind: optional limits (max size per file in MB, max number of files, max total in MB), a note to the sender (≤ 500 chars, counter), expiry and optional password as today; no max-downloads field. The created link is shown/copied like today, labelled as a request link.
2. My links (web/src/views/SharesView.vue) and the admin links list: show the kind (icon + label) and for upload links the files/bytes received so far and the limits.
3. Public page (web/src/views/ShareLinkView.vue, route /s/:token): when the info answer has `kind: 'upload'`:
   - Password step as today when needed.
   - Folder name, the owner's note as PLAIN TEXT (never v-html), limits and expiry; a large drop zone + "Choose files" button (multiple files, no folders); each file uploads in chunks through /api/s/:token/upload, PUT …/:id/:n, POST …/:id/complete (reuse the chunk logic in web/src/upload-utils.js where it fits; send no CSRF header, the visitor cookie is set by the server) with a progress bar per file, cancel (DELETE …/:id), and a clear error per file (too big, link full, busy, quota of the owner full) without stopping the others.
   - "Files you sent" list from the answer's `mine`, updated after each completion. Nothing else of the folder is ever shown.
   - Works without an account and without being signed in; at 375 px the drop zone becomes a big button.
4. Quota feedback for signed-in users: when an upload, copy, unzip or save answers `quota.exceeded`, show the server message (it includes used/quota) and, in the upload panel, which file failed; the file page shows a small usage line/bar (GET /api/me/usage) for a user with a quota — next to the existing storage info, not a new page.
5. Every new string in th and en in web/src/i18n.js.
6. Browser check (1200 px and 375 px, th and en): create an upload link with limits and a password, open it in a second browser context (not signed in), unlock, upload 3 files with progress (one with a name that already exists in the folder → saved under a new name), hit the per-file limit and the file-count limit, see "Files you sent"; confirm the folder's other files are never visible; the owner sees the counts in My links; a user with a 1 MB quota gets the quota message on upload.
