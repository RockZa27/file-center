# File Center (ElysiaJS)

ระบบฝากและแจกจ่ายไฟล์บนเว็บ เขียนใหม่ทั้งหมดด้วย **ElysiaJS + Bun** (backend) และ **Vue 3 + Naive UI** (frontend)
ออกแบบให้ใช้งานและหน้าตาใกล้เคียง File Center ที่สร้างต่อจาก FileGator แต่ไม่ได้ใช้โค้ดหรือข้อมูลเดิมเลย

- **ผู้เยี่ยมชม** เปิดเว็บแล้วดาวน์โหลดไฟล์ในโฟลเดอร์สาธารณะได้ทันที (ปิดได้จากหน้าตั้งค่า)
- **ผู้ใช้** เข้าสู่ระบบแล้วจัดการไฟล์ในโฟลเดอร์ของตัวเอง และใช้โฟลเดอร์สาธารณะตามสิทธิ์ที่ได้รับ
- **ผู้ดูแลระบบ** จัดการไฟล์ทั้งหมด ผู้ใช้ สิทธิ์ ดูสุขภาพระบบ ประวัติการใช้งาน ถังขยะ และตั้งค่าเว็บ

## เริ่มใช้งาน

ต้องมี [Bun](https://bun.sh) 1.1 ขึ้นไป

```bash
bun install
bun run build      # คอมไพล์หน้าเว็บ (ถ้าไม่มี Node ในเครื่องให้ใช้: bun --bun run build)
bun start          # เปิดที่ http://localhost:3000
```

ครั้งแรกระบบสร้างบัญชี `admin` ให้และ **แสดงรหัสผ่านที่สุ่มไว้ในหน้าจอ** (จะบังคับให้เปลี่ยนทันทีที่เข้าสู่ระบบ)
หรือกำหนดเองด้วย `ADMIN_PASSWORD=...` ก่อนเริ่มครั้งแรก

ระหว่างพัฒนา:

```bash
bun run dev        # API ที่ :3000 + หน้าเว็บ (Vite, hot reload) ที่ :5173
bun test           # ทดสอบ API 30 รายการ
bun run typecheck
```

## รันด้วย Docker และย้ายเครื่อง

```bash
cp .env.example .env     # แก้ ADMIN_PASSWORD ถ้าต้องการ
docker compose up -d --build
docker compose logs file-center   # ดูรหัสผ่าน admin ที่สุ่มให้ครั้งแรก
```

ข้อมูลทั้งหมดอยู่ในโฟลเดอร์ `./data` ข้างไฟล์ `docker-compose.yml` เท่านั้น:

- `data/storage/` ไฟล์ที่อัปโหลด
- `data/system/` ผู้ใช้ การตั้งค่า โลโก้ ประวัติ ถังขยะ session และไฟล์อัปโหลดที่ยังไม่เสร็จ (เป็นไฟล์ JSON ธรรมดา ไม่มีฐานข้อมูลแยก)

**ย้ายไปเครื่อง server ใหม่:** `docker compose down` ที่เครื่องเดิม → คัดลอก **ทั้งโฟลเดอร์โปรเจกต์** (รวม `data/` และ `.env`) ไปเครื่องใหม่ → `docker compose up -d --build`
ไม่ต้องแก้ค่าใดๆ ผู้ใช้ รหัสผ่าน ไฟล์ ถังขยะ และประวัติจะอยู่ครบ ผู้ที่ login อยู่ยัง login ต่อได้ ข้อมูลไม่มีพาธเครื่องเดิมฝังอยู่
(ควร `down` ก่อนคัดลอกเพื่อให้ไฟล์ข้อมูลนิ่ง และเครื่องใหม่ต้องมี Docker กับ Docker Compose v2)

## ตั้งค่า (ตัวแปรสภาพแวดล้อม)

| ตัวแปร | ค่าเริ่มต้น | ความหมาย |
|---|---|---|
| `PORT` / `HOST` | `3000` / `0.0.0.0` | พอร์ตและที่อยู่ที่เปิดรับ |
| `STORAGE_DIR` | `./storage` (Docker: `/data/storage`) | ที่เก็บไฟล์ที่อัปโหลด |
| `DATA_DIR` | `./data` (Docker: `/data/system`) | ผู้ใช้, ตั้งค่า, session, log, ถังขยะ, ไฟล์อัปโหลดที่ยังไม่เสร็จ |
| `ADMIN_PASSWORD` | สุ่ม | รหัสผ่านของ admin ตอนสร้างบัญชีครั้งแรก |
| `UPLOAD_MAX_SIZE` | 10 GB | ขนาดสูงสุดต่อไฟล์ (ไบต์) |
| `UPLOAD_CHUNK_SIZE` | 8 MB | ขนาดชิ้นส่วนที่หน้าเว็บส่งทีละชิ้น |
| `UPLOAD_SIMULTANEOUS` | 3 | จำนวนชิ้นที่ส่งพร้อมกัน |
| `UPLOAD_STALE_HOURS` | 3 | ลบอัปโหลดที่ไม่เสร็จและไม่มีชิ้นใหม่เข้ามาเกินกี่ชั่วโมง |
| `TRASH_RETENTION_DAYS` | 30 | เก็บถังขยะกี่วัน |
| `SESSION_TTL_HOURS` | 168 | อายุ session ของผู้ที่เข้าสู่ระบบ (ไม่ได้ใช้งานเกินนี้จะหมดอายุ) |
| `LOGIN_MAX_ATTEMPTS` / `LOGIN_LOCKOUT_SECONDS` | 5 / 60 | ล็อกการเข้าสู่ระบบผิดซ้ำ (นับแยกตาม IP + ชื่อผู้ใช้) |
| `SECURE_COOKIE` | `false` | ตั้งเป็น `true` เมื่อใช้ผ่าน HTTPS |
| `TRUST_PROXY` | `false` | ตั้งเป็น `true` เมื่ออยู่หลัง reverse proxy เพื่ออ่าน IP จาก `X-Forwarded-For` |

## สิทธิ์

บทบาท: `admin` เห็นทุกโฟลเดอร์ / `user` เห็นเฉพาะโฟลเดอร์ส่วนตัว (ผู้ดูแลเลือกได้ ค่าเริ่มต้น `/users/<ชื่อผู้ใช้>`) /
ผู้เยี่ยมชมเห็นเฉพาะโฟลเดอร์สาธารณะ (`storage/public`)

สิทธิ์ที่กำหนดได้: `read` ดูรายการ · `download` · `batchdownload` ดาวน์โหลดหลายไฟล์เป็น zip · `upload` ·
`write` สร้าง/แก้ไข/เปลี่ยนชื่อ/คัดลอก/ย้าย/ลบ · `zip` บีบอัดและแตกไฟล์

ผู้ใช้แต่ละคนมีชุดสิทธิ์ 2 ชุดแยกกัน คือในโฟลเดอร์ของตัวเอง และในโฟลเดอร์สาธารณะ ส่วนสิทธิ์ของผู้เยี่ยมชมตั้งที่หน้า "ตั้งค่า"
สิทธิ์ถูกตรวจที่ server ทุกคำสั่ง ไม่ใช่แค่ซ่อนปุ่มในหน้าเว็บ

## โครงสร้าง

```
src/
  index.ts          ประกอบแอป, เสิร์ฟหน้าเว็บ, งานเบื้องหลังรายชั่วโมง
  config.ts         ค่าตั้งต้นและตำแหน่งโฟลเดอร์
  auth.ts           ผู้ใช้, session, ล็อกการเข้าสู่ระบบ, การแปลงสิทธิ์เป็นพื้นที่ที่เข้าถึงได้
  context.ts        ตรวจ session/CSRF, รูปแบบ error เดียวกันทุก API
  fsx.ts            จัดการพาธอย่างปลอดภัย (กัน ../ และ symlink), คัดลอก/ย้าย
  zip.ts            สร้าง zip แบบ stream และแตก zip (กัน zip-slip / zip bomb)
  uploads.ts        อัปโหลดแบบแบ่งชิ้น กลับมาต่อได้
  trash.ts, audit.ts, settings.ts, store.ts
  routes/           session, files, upload, admin
web/                Vue 3 + Naive UI (build ไปที่ web/dist)
tests/api.test.ts   ทดสอบ API
```

ข้อมูลทั้งหมดเป็นไฟล์ธรรมดา (ไม่ต้องมีฐานข้อมูล) สำรองข้อมูลได้โดยคัดลอกโฟลเดอร์ `data/` (ถ้ารัน Docker) หรือ `storage/` กับ `data/` (ถ้ารันด้วย bun โดยตรง)

## การสำรองข้อมูลที่แสดงในหน้าภาพรวม

ระบบไม่ได้สำรองเอง ถ้าสคริปต์สำรองของคุณเขียนไฟล์ `data/backup-status.json` หน้าภาพรวมจะแสดงผลและเตือนเมื่อล้มเหลวหรือเก่าเกิน 2 วัน:

```json
{ "status": "ok", "lastSuccess": "2026-10-08T02:00:00Z" }
```

(`status` เป็น `"ok"` หรือ `"failed"`)

## API โดยสรุป

ทุกคำสั่งที่เปลี่ยนข้อมูลต้องส่งหัว `X-CSRF-Token` ที่ได้จาก `GET /api/session` ผิดพลาดตอบเป็น `{ "error": "ข้อความ" }`

| | |
|---|---|
| `GET /api/session` · `POST /api/login` · `POST /api/logout` · `POST /api/password` | เซสชัน |
| `GET /api/list` · `/api/folders` · `/api/search` | ดูรายการ ค้นหา (พารามิเตอร์ `space=home\|public`, `path`) |
| `POST /api/mkdir` · `/newfile` · `/rename` · `/copy` · `/move` · `/delete` · `/zip` · `/unzip` | จัดการไฟล์ (ลบ = ย้ายไปถังขยะ) |
| `GET/PUT /api/content` | อ่าน/บันทึกไฟล์ข้อความ (≤ 2 MB) |
| `GET /api/download` (รองรับ `Range`) · `POST /api/batch` + `GET /api/batch/:token` | ดาวน์โหลด |
| `POST /api/upload` → `PUT /api/upload/:id/:n` → `POST /api/upload/:id/complete` | อัปโหลดแบบแบ่งชิ้น |
| `/api/admin/*` | ผู้ใช้, ภาพรวม, ประวัติ, ถังขยะ, ตั้งค่า, โลโก้ (เฉพาะ admin) |
| `GET /api/health` | ตรวจสุขภาพ (ใช้กับ Docker healthcheck) |

## ต่างจาก FileGator ต้นแบบอย่างไร

- ไม่มีการ `chmod` ผ่านหน้าเว็บ (ไม่มีความหมายบน Windows/Docker)
- รหัสผ่านเก็บด้วย argon2id ผู้ใช้เดิมจาก FileGator ย้ายมาไม่ได้ ต้องสร้างใหม่ (ตามที่ตั้งใจไว้ว่าเริ่มใหม่ทั้งหมด)
- API เป็น REST (`/api/...`) ไม่ใช้รูปแบบ `/?r=/route`
- ไฟล์ที่ซ้ำชื่อตอนอัปโหลดจะถูกตั้งชื่อใหม่ เช่น `report (1).pdf` ไม่เขียนทับ
- session ของผู้เยี่ยมชมอยู่ในหน่วยความจำและมีเพดาน ส่วน session ของผู้ที่เข้าสู่ระบบเก็บในดิสก์ จึงอยู่รอดหลังรีสตาร์ต

## ข้อจำกัดที่ควรรู้

- พัฒนาและทดสอบบน Linux เท่านั้น ยังไม่ได้ลองบน Windows (พาธ, `statfs`, ชื่อไฟล์ต้องห้ามของ Windows) ให้ทดลองก่อนใช้งานจริง
- `Dockerfile` และ `docker-compose.yml` ยังไม่ได้ทดสอบ build (ทดสอบได้เฉพาะส่วนข้อมูลย้ายเครื่อง โดยรันด้วย `STORAGE_DIR`/`DATA_DIR` แบบเดียวกับใน Docker)
- ชื่อไฟล์ที่ไม่ใช่ ASCII ส่งไปในหัว `Content-Disposition` ตามมาตรฐาน RFC 6266 (`filename*=UTF-8''...`) ควรลองดาวน์โหลดไฟล์ชื่อไทยในเบราว์เซอร์ที่ใช้จริงอีกครั้ง
- ชื่อไฟล์/โฟลเดอร์ห้ามมีอักขระ `\ / : * ? " < > |` (เพื่อให้ย้ายข้ามระบบปฏิบัติการได้)
- ค้นหาไฟล์ตามชื่อโดยเดินดูโฟลเดอร์ตอนค้นหา ไม่มีดัชนี จึงช้าลงถ้ามีไฟล์หลักแสนไฟล์ขึ้นไป (จำกัดที่ 50,000 รายการต่อการค้นหา)
